# Styling

How archwindows turns an Omarchy theme into colours and fonts on Windows: what it styles, where each
colour comes from, which Windows mechanism carries it, how it is undone, and what cannot be styled.
The rule throughout is **follow Omarchy exactly**. The palettes are Omarchy's, and every derived
colour uses the rule Omarchy's own shell or terminal template uses, so a theme looks the same on
both.

Reference checkout: <https://github.com/basecamp/omarchy>. The files referred to below as
`omarchy:` paths are in that repo.

---

## 1. Palettes

| | |
|---|---|
| Source | `omarchy:themes/<name>/colors.toml` (23 themes) |
| In the exe | `src/themes.gen.h`, generated by `tools/import_themes.py <omarchy-checkout> assets` |
| Format | one row per theme: name, `light` flag (`mode = "light"`), background-image count, 25 colours as `COLORREF` (`0x00BBGGRR`) |
| Access | `EmbeddedThemes` / `Palette` in `src/theme.h` |

The 25 colour roles, in order (`gen::Color`):

```
background dark_background darker_background lighter_background
foreground dark_foreground light_foreground bright_foreground
accent selection muted
red yellow orange green cyan blue magenta brown
bright_red bright_yellow bright_green bright_cyan bright_blue bright_magenta
```

`last-horizon`, `solitude` and `white` have no `orange` / `brown` in Omarchy; the importer fills
them, and nothing in the shell uses those two roles.

**Accuracy check.** The embedded palettes were compared with the current Omarchy `colors.toml`
files role by role: 0 differences. Re-run that comparison (or re-import) whenever Omarchy's themes
change.

Theme assets (previews, backgrounds) live in `assets/themes/<name>/` (`p.jpg`, `b0.jpg`...), also
produced by the importer; the picker shows them and sets the wallpaper (`SpiWallpaper`,
`src/platform.h`).

## 2. Derived colours (shell UI)

Omarchy's shell draws with Qt, using alpha over the background. GDI has no alpha for these
surfaces, so each "colour at N% opacity" becomes an opaque `sys::mix(background, colour, N)`. The
rules live in `Palette` (`src/theme.h`) and come from `omarchy:default/themed/shell.toml.tpl` and
`omarchy:shell/Commons/{Color,Style}.qml`.

| `Palette::` | Rule | Omarchy source |
|---|---|---|
| `bg()` / `fg()` / `accent()` | `background` / `foreground` / `accent` | `[bar] text`, `[popups] text`... all `{{ foreground }}` |
| `dim()` | `Qt.darker(foreground, 1.4)` (each channel × 10/14), floored at 3:1 vs background | `PanelHero` meta text |
| `faint()` | foreground at 50% | unused workspaces, `opacity: 0.5` |
| `idleFill()` / `idleBorder()` | foreground 4% / 40% | `[controls] normal-*` |
| `hover()` / `hoverBorder()` | foreground 8% / 25% | `[controls] hover-cursor-*` |
| `selected()` | foreground 18% | `[controls] selected-fill-alpha` |
| `menuBorder()` | foreground | `[menu] border = active-border-foreground` |
| `menuSelected()` / `menuSelectedBorder()` | foreground 8% / 25% | `[menu] selected-background(-alpha)`, `selected-border-alpha` |
| `accentText()` | accent, lifted toward `bright_foreground` only if under 3:1 on `selected()` | `[menu] selected-text = accent` |
| `borderActive()` | accent | Hyprland `active_border` (Omarchy: gradient or `accent`) |
| `borderInactive()` | `rgba(595959aa)` over background | Hyprland `inactive_border` |

Contrast helpers (`src/sys.h`): `sys::luminance` (WCAG relative luminance via a 256-entry sRGB→linear
table, no `pow()`), `sys::contrast` (ratio ×100) and `sys::ensure(c, bg, min, toward)`. `ensure`
moves `c` toward `toward` in 5% steps only until it reaches the minimum, so colours that already
pass are returned unchanged. It is used only as a safety floor (`dim`, `accentText`); everything
else is Omarchy's exact rule.

### Where each surface takes its colours

**Bar** (`src/bar.h`, one per monitor, 26 px at 96 dpi like Omarchy's `size-horizontal`)
- background `bg`, text and icons `fg`, bottom hairline foreground 12%
- logo and active-workspace dot `fg`; unused workspace numbers `faint`
- hover: `hover` fill with `accentText` glyph; battery at 15% or less (not charging) `red`

**Menu** (`src/menu.h`, Super+Space)
- background `bg`, 2 px frame `menuBorder` (foreground)
- prompt (`Go…`) and breadcrumbs `dim`; labels `fg`
- selected row `menuSelected` fill + `menuSelectedBorder` outline, label and icon `accentText`
- app rows show the app's own colour icon (`IShellItemImageFactory`); every other row uses a glyph
- every entry is a plain row, as in Omarchy; lock / sleep / sign out / restart / shut down are rows
  under System, not buttons
- path detail (Omarchy's `parentPathFor`, parents joined with ` › `), as a `dim` second line in search
  results and on the Apps page: `Setup`, `Trigger › Capture`, `Apps › Inno Setup 6` (the app's Start
  Menu folders). Rows on the top-level page show none.

**Panels** (`src/ui.h` toolkit; `net.h`, `audio.h`, `display.h`, `panels.h`, `agents.h`, `bt.h`)
- background `bg`, 2 px frame `accent` (Omarchy `[popups] border = hyprland.active-border`)
- hero title `fg` bold, subtitle `dim` spaced capitals; section captions `dim` spaced capitals
- rows: hover `hover`, selected `selected`; labels `fg`, second lines `dim`
- choice buttons (DNS, scale, power mode): idle/hover/selected states as in the table above
- sliders: track foreground 16%, fill and knob `fg`; switch: on = foreground 22% track with an `fg` knob
- Claude mark `#D97757` (Anthropic's brand colour, as in Omarchy's agents panel)

**Theme picker** (`src/picker.h`): `fg` rows, `accentText` for the highlighted one, `accent` title.

## 3. Fonts

| Use | Font | How it gets there |
|---|---|---|
| All shell text | **JetBrains Mono** (Omarchy's `JetBrainsMono Nerd Font` minus the Nerd glyphs) | `assets/fonts/JetBrainsMono-{Regular,Bold}.ttf` v2.304, loaded with `AddFontResourceEx(FR_PRIVATE)` by `Assets::loadFonts()` at startup, visible to this process only |
| Fallbacks | `JetBrainsMono Nerd Font` → `JetBrainsMono NF` → `JetBrains Mono` → `Cascadia Mono` → `Consolas` | `Fonts::pickFace()`; the log prints the chosen face (`font: ...`) |
| Logo, Claude mark | `omarchy.ttf` (U+E900 Omarchy, U+E90E Claude) | embedded in the exe (`src/omarchyfont.gen.h`), `AddFontMemResourceEx` |
| Icons | Segoe Fluent Icons (ships with Windows 11), fallback Segoe MDL2 Assets | system font |

Sizes (96 dpi, scaled per monitor DPI; Omarchy's `[font] base-size = 12`):

| `Font` | Use | Size |
|---|---|---|
| `F_TEXT` | bar, panel body | 12 px |
| `F_SMALL` | second lines, battery % | 11 px |
| `F_ROW` | menu rows, prompt | 14 px |
| `F_BOLD` | panel titles | 14 px bold |
| `F_CAPTION` | section captions (drawn with 1 px letter spacing) | 10 px bold |
| `F_TITLE` | picker title | 16 px bold |
| `F_ICON` / `F_BIGICON` / `F_HERO` | glyphs / power buttons / panel hero | 14 / 18 / 24 px |
| `F_LOGO`, `F_OMA`, `F_OMAHERO` | Omarchy font | 16 / 15 / 26 px |

All text is GDI with `CLEARTYPE_QUALITY`.

**Glyph rule:** an icon codepoint (U+E700–U+F8FF) must be drawn with an icon font (`F_ICON`,
`F_BIGICON`, `F_HERO`). JetBrains Mono, unlike Consolas, does not fall back to Segoe glyphs, so a
codepoint drawn in a text font renders as a box. The menu chevron was one such bug.

**Glyphs used** (Segoe Fluent Icons; all checked to exist in `SegoeIcons.ttf`):
wifi `E701 E874 E873 E872`, no network `EB5E`, ethernet `E839`, bluetooth `E702`, volume
`E992–E995`, mute `E74F`, speaker row `E767`, mic `E1D6`, display `E7F4`, laptop `E7F8`, battery
`E850–E859`, `E83F` (full), charging `EBAB–EBB5`, power `E7E8`, lock `E72E`, sleep `E708`,
sign out `E748`, restart `E777`, refresh `E72C`, check `E73E`, chevrons `E76B E76C`,
calendar `E787`, speed `EC4A`, terminal `E756`, add `E710`, close/forget `E711`, headset `E7F6`,
keyboard `E765`, mouse `E962`, phone `E8EA`, gamepad `E7FC`.

Thin glyphs (the mic) can show orange/blue edges: that is ClearType sub-pixel rendering, not colour.

## 4. Other apps' windows (`src/winstyle.h`, option "Theme window colours")

`WindowWatcher` follows foreground and show events. `DwmStyle::apply` sets, per top-level window:

| DWM attribute | Value |
|---|---|
| `DWMWA_USE_IMMERSIVE_DARK_MODE` | `!light` |
| `DWMWA_WINDOW_CORNER_PREFERENCE` | do not round (tiling look) |
| `DWMWA_BORDER_COLOR` | `borderActive()` / `borderInactive()` |
| `DWMWA_CAPTION_COLOR`, `DWMWA_TEXT_COLOR` | `bg`, and `fg` / `dim` (classic title bars only) |

**Apps that draw their own title area** (Explorer, Windows Terminal, Chromium browsers, Snipping
Tool and other XAML/WinUI apps) get only the border and dark/light. Their title row is
semi-transparent when unfocused, so a DWM caption colour shows through as a tinted strip.
`DwmStyle::ownTitleArea()` detects them by behaviour rather than class name: their client area starts
at the top of the frame (client top − `DWMWA_EXTENDED_FRAME_BOUNDS` top < half a caption). A classic
window has its caption above the client area. Windows whose caption the tiler stripped also match;
with no caption, the colour has nothing to paint.

`--reset` and turning the option off call `DwmStyle::reset`, which puts back the system defaults.

## 5. Windows itself (`src/systheme.h`, option "Theme drives Windows dark/light and accent")

- `AppsUseLightTheme`, `SystemUsesLightTheme` ← the theme's `light` flag.
- `DWM\AccentColor`, `Explorer\Accent\{AccentColorMenu, StartColorMenu, AccentPalette}` ← `accent`
  (`AccentPalette` is an 8-step ramp mixed toward white/black).
- Broadcast `WM_SETTINGCHANGE("ImmersiveColorSet")` on a worker thread, as Settings does.
- Originals are backed up once in `HKCU\Software\ArchWindows\SysThemeBackup` and restored when the
  option is turned off, on quit, by `--reset`, or at the next start after a crash.
- Only committed themes are applied, never picker previews.

## 6. Terminals (`src/termtheme.h`, option "Theme drives terminal colours")

**ANSI mapping: exactly Omarchy's `omarchy:default/themed/alacritty.toml.tpl`.**

| Slot | Colour | Slot | Colour |
|---|---|---|---|
| background | `background` | foreground | `foreground` |
| cursor | `bright_foreground` | selection | `selection` (Omarchy's `selection_background`) |
| 0 black | `background` | 8 bright black | `muted` |
| 1–6 | `red green yellow blue magenta cyan` | 9–14 | `bright_red … bright_cyan` (same order) |
| 7 white | `foreground` | 15 bright white | `bright_foreground` |

Omarchy also defines `selection_foreground = bright_foreground`. Windows Terminal schemes have no
selection text colour, so selected text keeps its own colour there.

**Targets**

| Terminal | What is written | Live? |
|---|---|---|
| Windows Terminal (stable, Preview, unpackaged) | an `archwindows` colour scheme + `profiles.defaults.colorScheme`; an `archwindows` window **theme** (`themes[]` + root `"theme"`): `applicationTheme` light/dark, tab row foreground 8% over background, unfocused tab 4%, selected tab = terminal background | yes (Terminal reloads `settings.json`) |
| Classic console (`conhost`) | `HKCU\Console\ColorTable00..15` | new windows; open consoles are recoloured live via `AttachConsole` + `SetConsoleScreenBufferInfoEx` |
| mintty / Git Bash | `~/.minttyrc` colour keys | new windows |
| Bash (Git Bash) | `~/.archwindows-term` + a marked block in `~/.bashrc` that sends OSC colour codes from `PROMPT_COMMAND` | next prompt |

`settings.json` is edited in place by a small JSONC scanner (comments kept, only our members
touched). Without the window theme, light palettes kept Terminal's default dark tab row.

Originals (previous `colorScheme`, previous `theme`, `.minttyrc`, the console table) are backed up
once under `HKCU\Software\ArchWindows\TermThemeBackup` (values `wt<N>`, `wtt<N>`, `mintty`,
`console`) and restored when the option is turned off. A value the user changed since is left alone.

Not done: Terminal's font. Omarchy's terminals use JetBrains Mono; Windows Terminal needs the font
installed for the user, and `profiles.defaults.font.face` set.

## 7. Browsers (`src/browsertheme.h`, option "Theme drives Chrome / Brave colour", default on)

Mirrors `omarchy:bin/omarchy-theme-set-browser`:

- Policies, per user (HKCU) for Chrome, Brave and Edge:
  `BrowserThemeColor` = the theme's browser colour, `BrowserColorScheme = "device"`.
- Browser colour = Omarchy's `themes/<name>/chromium.theme`:
  flexoki-light `#f2f0e5`, last-horizon `#0c0b0c`, lumon `#0e1f29`, retro-82 `#00172e`,
  rose-pine `#d2c4db`. Other themes use a neutral seed: Omarchy's `#1c2027` for dark themes, and
  `#eeeeee` for light ones, because Chrome derives light/dark from the seed and a dark seed makes it
  go dark even with Windows in light mode.
- Chrome builds a whole tonal palette from the seed. Seeding with the theme background instead
  (tried first) tinted the browser strongly, e.g. saturated yellow on flexoki-light.
- Running browsers are told to reload policies with
  `<exe> --refresh-platform-policy --no-startup-window`, as Omarchy does. A Windows policy refresh
  (`RefreshPolicyEx`) did not reach Chrome. Browsers that are not running pick the colour up at start.
- Chrome may show "Managed by your organization" while a policy is set.
- Removed (only values we wrote, marker `HKCU\Software\ArchWindows\BrowserThemeSet`) when the option
  is turned off or by `--reset`.

## 8. Explorer and classic controls (visual styles)

The DWM border/dark mode (section 4) and dark/light (section 5) are as far as documented APIs go.
Explorer's content area, buttons, scrollbars and other classic controls are drawn by the visual
style (`.msstyles`), which Windows only loads if Microsoft signed it.

- `tools/make_msstyles.py <theme>` builds a recoloured copy of Aero: PNG assets and `COLOR`
  properties remapped from foreground…background, with blues replaced by the accent.
- Loading it needs a visual-style patcher. The installer bundles **SecureUxTheme** (LGPL, pinned
  SHA-256) and the styles in `build/msstyles`, then applies one after the reboot.
- Today only `retro-82` is bundled, and switching shell themes does not switch the visual style.
  Following every theme would mean generating all 23 styles and applying the matching one on commit.

## 9. Colour management

What Omarchy does on Arch (`omarchy:default/hypr/looknfeel.lua`, `wide-gamut.lua`):

- `cm_auto_hdr = 0`: keep HDR displays in SDR, because HDR washed out SDR content.
- A wide-gamut sRGB mapping **only on Apple Silicon** (the Asahi driver cannot signal sRGB). Its own
  comment says a PC must not do this, because it would convert twice and wash the colours out.
- No fontconfig rendering tweaks; just the font family.

Windows equivalents: keep Windows HDR / Advanced Colour off for the desktop; leave colour management
alone. A wide-gamut monitor in its native mode shows sRGB over-saturated; its own sRGB preset is the
fix. ClearType contrast (`HKCU\Control Panel\Desktop\FontSmoothingGamma`; 1000 is lighter than the
1200 default) affects how heavy text looks.

The `DisplayConfigGetDeviceInfo(DISPLAYCONFIG_DEVICE_INFO_GET_ADVANCED_COLOR_INFO)` query reports
HDR support, whether it is on, and wide-gamut capability per display, if you need to check.

## 10. Reviewing colours

```
python tools/palette_report.py [out.html]      # default: build/palette-report.html
```

It mirrors sections 2, 4 and 6 for every theme. For each one it draws a mock bar, active and
inactive windows, the menu, a slider and a terminal (`ls` colours, a comment in bright black, a
selected line, warnings, cursor). It also lists the 16 ANSI swatches and a WCAG contrast table, and
prints every pair below threshold:

| Pair | Minimum |
|---|---|
| body text, terminal text | 4.5:1 |
| UI text, icons, accent text, frames, active border, ANSI colours | 3:1 |
| bright black (comments) | 2.2:1 |
| unused workspace numbers | 2:1 |
| inactive border | 1.3:1 |
| selection fill vs background | 1.25:1 |

**Keep the script's mappings in sync with `theme.h`, `winstyle.h` and `termtheme.h`.**

Current result: every shell surface passes on all 23 themes. The remaining items are theme ANSI
colours that are low by Omarchy's own design, so they look the same in Omarchy's terminals. Left
exact on purpose:

- catppuccin-latte, flexoki-light, rose-pine: yellow, magenta and/or cyan
- matte-black, lupine: some brights
- miasma, solitude: red / bright green
- several dark themes: bright black (`muted`)
- vantablack: selection close to the background

A minimum-contrast option for the terminal could lift these if readability is preferred to
exactness.

## 11. Bar and window layout notes that affect the look

- The Windows taskbar is hidden while the shell runs and switched to auto-hide, so its strip is
  released and tiled/maximised windows reach the bottom edge. The original state is kept in
  `HKCU\Software\ArchWindows\TaskbarState` and restored on quit or `--reset`.
- The bar reserves its strip as an app bar on every monitor (`SHAppBarMessage`). The tiler re-reads
  the work area on `WM_SETTINGCHANGE(SPI_SETWORKAREA)` and relays out.
- Tiling gaps: 10 px outer, 5 px inner (option "Gaps between windows"); the wallpaper shows through
  them. Corners are square.

## 12. Adding or changing a surface: checklist

1. Take the colour from Omarchy's matching template (`omarchy:default/themed/*.tpl`, the shell's
   `shell.toml.tpl` section, or its QML) rather than inventing a mix.
2. Add or reuse a named `Palette::` helper; do not scatter `sys::mix` percentages through
   drawing code.
3. Draw icon codepoints only with an icon font.
4. Accent used as text on a fill: `accentText()`. Frames and borders: `accent()`.
5. Anything written outside the process (registry, files, policies) gets a one-time backup and a
   restore path in both `--reset` and "option turned off".
6. Mirror the rule in `tools/palette_report.py` and re-run it.
